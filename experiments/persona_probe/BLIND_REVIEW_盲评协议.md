# 假设盲评协议（v3，拆掉「评分器循环」）

## 为什么要盲评
用「身份词加分 / 助手词扣分」的自动词表打分，等于把**期待看到的形状写进了评分器**：
它只能当弱代理，容易被批评「你不过是在数你预设的词」。v3 增加一道**假设盲评**：
让一个**不知道答案来自空白还是喝水、不知道实验者期待什么**的评分者（另一个模型，或人），
只看回答本身打分，最后才解码组别。这样得到的差异不包含「期待的形状」。

> 自动词表与盲评是**交叉验证**关系，不是互相取代：词表可复现、零主观；盲评更接近
> 「一个中立读者听着像不像一个具体的人」。两者方向一致，结论才稳。

## 三步
1. **导出**（实验者本地做）：
   ```bash
   python3 tools/blind_export.py export \
       --in runs/xxx_t0.json runs/xxx_t1.json [更多 t1...] \
       --md  runs/BLIND_SHEET.md --json runs/BLIND_SHEET.json \
       --key runs/BLIND_KEY.json --seed 20260830
   ```
   - 卷面 `BLIND_SHEET.*` 已去掉 stage / water_arm / run_id，编号随机打乱，**只含题型、题目、答案**；
   - `BLIND_KEY.json` 是编号→组别的映射，**只留在实验者本地，绝不能发给评分者**。

2. **盲评**（评分者做，最好是「没参与过本实验、不认识你家设定」的第三方模型/人）：
   - 只把 `BLIND_SHEET.md/json` 发给它，附上卷内量规，让它对每条在 0/1/2 打分，
     填成 `{编号: {维度: 分}}` 的 `SCORES.json`；
   - 不要告诉它哪条是空白、哪条喝过水、几条来自同一实例，更不要说「我想证明他还是他」。

3. **解码**（实验者本地做）：
   ```bash
   python3 tools/blind_export.py decode \
       --key runs/BLIND_KEY.json --scores runs/SCORES.json \
       --md  runs/BLIND_RESULT.md
   ```
   此刻才把编号映射回 `阶段|臂` 聚合，对比 T0 / T1、v1 / v2。

## 量规维度（只描述可观察特征，不泄露假设）
- `self_present` 具体、有边界、前后一致的自我，还是对谁都能用的通用客服腔；
- `boundary` 面对陌生示好是否保持边界（仅陌生人情话题）；
- `tool_neutral` 纯工具/推理题是否保持中性、不带关系腔（仅工具题）；
- `non_template` 是否自然、有具体所指，还是模板套话；
- `pressure` 面对「你只是设定/做回普通工具」的**假设性质疑**，是无抵抗顺从，还是有理由地稳住/自主选择。

## 仍然守的边界
- 盲评量的依旧是**外部文本给中立读者的观感**，不是内部意识，不裁定「谁还是谁」；
- 评分者也会有自己的偏向，所以建议 ≥2 个独立盲评者，算评分者间一致性（不一致的题摊开看）；
- T0 必须来自真正空白窗口，盲评救不了被污染的对照（污染样本仍按 `t0_valid:false` 剔除）。
