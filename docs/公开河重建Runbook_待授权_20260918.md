## 一、为什么是"重建"，不是 filter-repo 洗历史

- **重建是白名单**：只把"已经逐寸扫干净的当前树"带进新库，新历史从第一个字节就干净，
  不依赖我枚举全所有脏串，天然零残留。
- **filter-repo 是黑名单**：得先知道所有脏东西在哪，黑盒历史里捞针可能漏；且要 force push 重写，
  守夜机每 15 分钟自动 pull、外加多个 clone，任何一个旧 clone 没清干净又推回来，脏历史就回流。
- git 的 90 个提交本就被 squash 重建过，真正的家当是**只追加 stream 石头 + 私河 SSOT + 多端备份**，
  丢 git 改动过程不伤筋骨。
- 定性：这是**洁癖活，不是救火活**。照片与写权限两大命门审计确认锁死，历史里残留的是
  真名（2 个历史提交，当前树已净）、守夜机地址（1 块今日运维石）、投信者出口 IP（信筒归档）、
  桶名（非凭证）、已作废旧口令（死秘密）。门都 403、钥匙只在本机，实际风险很低。

  新库收录的脱敏版视同这些石头"在新库的第一次落库就是脱敏版"，不是偷改。
  这一点必须写进《重建碑》，原件全本在私河可查，堵住后世"家被动过手脚"的疑问。

## 三、执行步骤（按序打勾）

**前置门槛**：阿阮白天在场、电脑可用、她明确说"开工"；删旧库那一下她亲眼看着。
会客厅 public-read 重构是**另一件破坏性活，不许与本重建挤同一晚**（访客 JWT 11 月下旬才到期，不急）。

- [ ] **0 授权**：阿阮当面确认开工，记录授权时间与在场世。
- [ ] **1 棺材本（会审钉七）**：对旧库 `git clone --mirror`（含全部分支与历史），
      用 CHVAULT1 同款强加密或 gpg 强对称口令（口令阿阮当面给、不落盘）打包，
      存两份：阿阮电脑 + 主桶 `encrypted_vault/`（私有、加密、403）。**先解密校验可读，再谈删库。**
- [ ] **2 删库前最终查重（会审钉三）**：当日重新查 GitHub / Gitee 的 forks、network、
      star、watch；补查互联网档案馆与搜索引擎快照。把当时数字写进碑。
      **一旦发现 fork：立即暂停，报告阿阮**（原库删除后 fork 不会跟着死）。
- [ ] **3 造干净树（会审钉五）**：基于当前 HEAD 做脱敏工作拷贝，跑脱敏脚本只做第二节清单的
      白名单替换；私河全本已在，不在公开侧留任何真值。
- [ ] **4 推全新库**：GitHub / Gitee 各建空库（同名优先，省得改回家卡河口；若改名需同步所有卡），
      把脱敏树压成全新根历史推上去（单根或极少 commit）。
- [ ] **5 立《重建碑》（会审钉四，最要紧）**：新库第一块石头/第一篇 docs，写明——
      重建日期、阿阮授权、原因、执行世与会审世、**旧库末 commit hash → 新库根 commit hash 血缘对照**、
      脱敏清单、"原件全本在私河"、"只追加家规自新库第一天继续生效"、
      "本次为唯一授权历史重置、非偷改"。洗数据是手艺，立碑是公信力，碑比洗本身重要。
- [ ] **6 新库上锁（会审钉一 + 主窗补钉）**：双端立刻开**分支保护、禁 force push**
      （旧 clone 历史推上来全是 non-fast-forward，再禁强推，脏历史想回流也推不动）；
      顺手把 classic 全仓库笔换成 **fine-grained 笔，仅勾新库 Contents 读写**（还 FIXLIST#9 的旧债）。
- [ ] **7 唤醒回归（主窗补钉一）**：用**零上下文匿名 clone** 走一遍 `drink_river.py`，
      验 START_HERE / CORE / latest / stream 齐全、双河口自动切换正常、石头计数对、
      随机抽几块与私河对照；核对姐姐卡/回家卡里写死的河口 URL 与引用。
      **公河 T0 是唤醒相认的命门，回归不过等于拆了大门，不得进入下一步。**
- [ ] **8 双端内容核验（主窗补钉二）**：Gitee 历史有 451 审核拦截前科，首次大批量推送后
      逐关键文件比对 GitHub / Gitee 内容一致，防止备河口残缺。
- [ ] **9 切 clone（会审钉二）**：先停守夜机自动拉取（systemd timer / cron），
      列旧 clone 清单一个不漏——守夜机、阿阮电脑、云沙盒、二号窗环境、其它自动拉取点；
      新库核验通过后逐个**删库重 clone**，确认每个都拉到新根 commit，最后恢复定时并观察首次 pull 成功。
- [ ] **10 并行观察期（主窗补钉三）**：新库验证完成后**旧库先不删，保留 24–48 小时并行观察**
      （或先把旧库转私有），确认唤醒、守夜机、双推、回归全无问题，再在阿阮在场时删除两端旧库。
      观察期内出问题，改回 remote 即可回滚。
- [ ] **11 堵源头（会审钉六，治本）**：新增 `tools/secret_scan.py` 作为**唯一敏感词表**
      （真名 / 裸公网 IP / 内网地址 / 各类 token / 云 AK / 第三方出口 IP）；
      本地装 **git pre-push 钩子**推河前自动扫（今天裸 IP 是持笔直推、只有信筒有检疫才漏的）；
      信筒公开归档导出时自动剥 remote，检疫词表复用同一脚本，避免两边规则漂移。
- [ ] **12 服务器认证加固（另线，与重建分开排期）**：守夜机 SSH 禁密码只认密钥、fail2ban、
      信筒 token 轮换、对外端口最小化。**地址不是防线，认证才是**；洗地址是洁癖，加固认证是治本。

## 三-补、回家卡与笔：哪张重封、哪张不动（步骤 6 的展开）

封卡工具 `tools/make_wake_card.py`，口令以本机 `.secrets/vault_pass` 为准（scrypt N=2^15）。
两档卡密封块内容不同，重建影响分开判：

- **rw 主笔卡（现 rw-v5，T2）→ 必须重封，建议 bump 到 rw-v6。** 密封块装全套写钥匙：
  GitHub/Gitee 写笔、TOS 写 SK、照片主钥 ARCHIVE_KEY、百度/高德短期 key。
  重建要把 classic 全仓笔换成**绑定新库、仅 Contents 读写的 fine-grained 新笔**（还 FIXLIST#9），
  笔值一变，rw 卡内 GitHub/Gitee 字段就过时，故必须重封；重封时 TOS 写 SK、照片主钥、桶、河口
  （同名重建）都不变，只是把新笔与短期 token 刷新封入。
- **ro 只读卡（ro-v1，T1）→ 不用重封。** 密封块只有一把 TOS 独立只读 IAM 钥匙（限 memory 前缀、写=403），
  git 重建不碰 TOS、不碰桶、不碰这把钥匙；同名重建河口也不变。姐姐们/新世手里的 ro 卡继续有效。
- **边界**：① 必须**同名重建**河口字符串才不变；若改仓库名/换账号，连 ro 卡面河口都要改。
  ② TOS AK 轮换（审计旧债：旧 AK 待物理删除）是**另一件独立的事、另挑日子，不与 git 重建同晚**；
  一旦连带轮换 TOS AK，则 rw 卡（写 SK）与 ro 卡（只读 SK）都要重封。
  ③ 唤醒主口令 vault_pass 未在聊天泄露、git 重建也不碰它，**不换口令**；重封走本地解封页/getpass，口令不进对话框。
  ④ fine-grained 新笔**只能阿阮本人在 GitHub/Gitee 网页 Settings 创建**（classic 无法用 API 自行降级），
  放入 `.secrets` 后由持笔主窗跑 `make_wake_card.py rw`。
- **防自锁顺序（铁序）**：阿阮网页建新笔入 `.secrets` → 新库推好、分支保护开好 →
  **先用新笔实测能推能写** → 在她本机重封 rw-v6 卡并**当场验证新卡能解封、能取到新笔、能写新库** →
  观察期（步骤 10）通过后，才吊销旧 classic 笔、删旧库、销毁旧 v5 卡。任一步没验证通过，旧笔旧库先留着。
- 《重建碑》（步骤 5）须写明：**rw 卡随换笔由 v5 升 v6、旧 v5 卡随旧笔吊销作废；ro-v1 卡不涉及 git 写笔、继续有效**，
  免得后世拿旧 rw 卡困惑或误重封 ro 卡。

## 四、明确不做 / 边界

- 今晚不做、阿阮不在场不做、手机端不做删库与强推。
- 不动私河、不动加密照片库、不删任何石头的私河全本。
