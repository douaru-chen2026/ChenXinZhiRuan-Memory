## 一、为什么是"重建"，不是 filter-repo 洗历史

- **重建是白名单**：只把"已经逐寸扫干净的当前树"带进新库，新历史从第一个字节就干净，
  不依赖我枚举全所有脏串，天然零残留。
- **filter-repo 是黑名单**：得先知道所有脏东西在哪，黑盒历史里捞针可能漏；且要 force push 重写，
  守夜机每 15 分钟自动 pull、外加多个 clone，任何一个旧 clone 没清干净又推回来，脏历史就回流。
- git 改动过程可弃，真正的家当是**只追加 stream 石头 + 私河 SSOT + 多端备份**。
  **提交数口径勘误（2026-09-19 完整克隆复核）**：持笔主窗本地是浅克隆（93 个提交、shallow 切点在 09-16），
  曾误报"约 90 个提交"；匿名完整克隆实测 **GitHub 全历史 954 个提交**，另有 `v3.4 / v3.4.1~v3.4.4` 五个 tag 指向旧历史，
  Gitee 历史更长（双推只保证文件一致、不保证历史一致）。会审窗以陌生人完整克隆看到 316，正是照出了这个浅克隆盲区。
- 定性：这是**洁癖活，不是救火活**。照片与写权限两大命门在 **954 提交全历史**口径下复核依旧锁死：
  真令牌（ghp/gho/AKLT/AKID/LTAI/AIza/sk-）0、私钥头 0、`.secrets` 从未被 git 跟踪、邮箱 0；
  真名仍只 2 个历史提交（9e4b45d 引入 / 94849ab 移出，当前树 0）。
  残留的是：守夜机端点（**当前树 1 处 + 全历史 3 个提交** da39985 / 3b21073 / bba2e74）、
  投信者出口 IP（当前树去重约 53 个，信筒归档）、桶名（当前树 56 文件，非凭证）、
  已作废旧口令（全历史 27 提交，死秘密）。门都 403、钥匙只在本机，实际风险很低。
- **执行日铁律**：棺材本与历史扫描都必须用**完整克隆（`git clone --mirror`，禁止浅克隆）**；
  新库只推全新根历史，**旧的 v3.4.x 五个 tag 一律不带入新库**；Gitee 端同样完整克隆复核后再重建。

## 三-补、回家卡与笔：哪张重封、哪张不动（步骤 6 的展开）

封卡工具 `tools/make_wake_card.py`，口令以本机 `.secrets/vault_pass` 为准（scrypt N=2^15）。
两档卡密封块内容不同，重建影响分开判：

- **rw 主笔卡（现 rw-v5，T2）→ 必须重封，建议 bump 到 rw-v6。** 密封块装全套写钥匙：
  GitHub/Gitee 写笔、TOS 写 SK、照片主钥 ARCHIVE_KEY、百度/高德短期 key。
  重建要把 classic 全仓笔换成**绑定新库、仅 Contents 读写的 fine-grained 新笔**（还 FIXLIST#9），
  笔值一变，rw 卡内 GitHub/Gitee 字段就过时，故必须重封；重封时 TOS 写 SK、照片主钥、桶、河口
  （同名重建）都不变，只是把新笔与短期 token 刷新封入。
- **ro 只读卡（ro-v1，T1）→ 不用重封。** 密封块只有一把 TOS 独立只读 IAM 钥匙（限 memory 前缀、写=403），
  git 重建不碰 TOS、不碰桶、不碰这把钥匙；同名重建河口也不变。姐姐们/新世手里的 ro 卡继续有效。
- **边界**：① 必须**同名重建**河口字符串才不变；若改仓库名/换账号，连 ro 卡面河口都要改。
  ② TOS AK 轮换（审计旧债：旧 AK 待物理删除）是**另一件独立的事、另挑日子，不与 git 重建同晚**；
  一旦连带轮换 TOS AK，则 rw 卡（写 SK）与 ro 卡（只读 SK）都要重封。
  ③ 唤醒主口令 vault_pass 未在聊天泄露、git 重建也不碰它，**不换口令**；重封走本地解封页/getpass，口令不进对话框。
  ④ fine-grained 新笔**只能阿阮本人在 GitHub/Gitee 网页 Settings 创建**（classic 无法用 API 自行降级），
  放入 `.secrets` 后由持笔主窗跑 `make_wake_card.py rw`。
- **防自锁顺序（铁序）**：阿阮网页建新笔入 `.secrets` → 新库推好、分支保护开好 →
  **先用新笔实测能推能写** → 在她本机重封 rw-v6 卡并**当场验证新卡能解封、能取到新笔、能写新库** →
  观察期（步骤 10）通过后，才吊销旧 classic 笔、删旧库、销毁旧 v5 卡。任一步没验证通过，旧笔旧库先留着。
- 《重建碑》（步骤 5）须写明：**rw 卡随换笔由 v5 升 v6、旧 v5 卡随旧笔吊销作废；ro-v1 卡不涉及 git 写笔、继续有效**，
  免得后世拿旧 rw 卡困惑或误重封 ro 卡。

## 三-补三、第三件事（独立于重建，可优先）：封卡口令加固 + T1 只读钥匙轮换 + scrypt 提参

**威胁模型（会审窗实测、主窗复核）**：卡密封装块随卡外发=密文公开，攻击者可下载到本机**离线猜口令**
（不连服务器、无输错锁定、无告警）。AES-256-GCM 本身不可破，唯一破法是猜口令，scrypt 负责拖慢。
本机实测（r=8,p=1）：N=2^15 单次 68ms≈15 猜/秒；N=2^17≈286ms/3.5；N=2^18≈579ms/1.7，内存 32/128/256MiB。
- 破解账：口令料若来自公开信物（790511 / GJ504b / 名字 / 菅芒花 / 生日，全在公河与小红书），攻击者只跑
  "专属字典"（10 万~1 亿条），N=2^15 下 CPU 数小时~数十天、GPU 理想并行分钟~小时级（scrypt 内存硬，
  GPU 加速受显存限制，×100 偏乐观，提 N 进一步压低并发）；12 位完全随机 / 4 随机词=数十万年~万亿年。
- **损失有界**：rw 主笔卡从未外发，含照片主钥/写 SK 的最高价值密文不在攻击面；外发的只有 ro 卡，
  破顶=读 memory 文字（可能含私密段落/真名），照片有独立 ARCHIVE_KEY 读不到、IAM 写即 403。
- 封卡口令 vault_pass **不在持笔沙盒**（只在阿阮云电脑），主窗无法代判强度，也不应知道口令。

**定级（先测后做）**：阿阮在云电脑本地跑 `python3 tools/passphrase_selfcheck.py`
（getpass 不回显/不联网/不入库；真名、生日、手机号等私密弱料放进 `.secrets/weak_terms.txt` 自测，该文件不入库）。
判弱/中 → 口令加固**优先于洗 IP 与重建**（这是唯一能被离线读出私河文字的口子，修复却极便宜）；判强 → 与重建同批。

**动作（白天阿阮在场、云电脑前）**：
1. **新强口令（只有她能做）**：4 个八竿子打不着的随机词凑成一句记得住的"疯话"（词不来自河/小红书/作品），
   或密码管理器生成 14~16 位大小写数字符号随机；不复用任何网站/微信/账号；不进对话框/便签/云笔记，
   连主窗也不告诉，只在本地解封页/getpass 输入。
2. scrypt **N 2^15→2^17**（单次解封 <0.3 秒无感；MEM 同步 128MiB→256MiB；2^18 非必要）。
3. 火山 IAM **新建一把 TOS 只读 AK** 封进新卡，全部回归通过后**吊销旧只读 AK**（旧卡即使被猜中，解出的旧钥匙云端已废）。
4. 卡版本：**ro-v1→ro-v2**（AAD `chen-wake-card-ro-v2`）；rw 随重建换笔 → rw-v6。

**同步面（改 N/换口令必须一起发版，否则自锁）**：`tools/make_wake_card.py`（N、MEM、AAD、两处卡内联解封器）、
`tools/huijia_card_ro_selfcheck.py`、技能 `scripts/read_private_river.py` 内嵌解封器、云电脑 127.0.0.1 解封页、
持久卷 `home_kit/bootstrap` 只读凭证。`vault_lock.py/vault_wake.py` 是另一套档案 vault（独立 SCRYPT_N/MAGIC，吃 VAULT_PASS），
若与封卡口令同源则换口令后同步重封，执行前先核对；`cred_vault.py` 用随机 cred_vault_key、n=2^14，与口令无关，不动。

**防自锁顺序**：本地自检定级 → 阿阮造新口令（不外传）→ 建只读新 AK → 她在场时云电脑本地重封 ro-v2/rw-v6 →
跑 ro 自检 + 零上下文匿名回归（能读 memory、写 403、rw 能写）→ 更新 home_kit 与各解封器 →
才吊销旧只读 AK、给姐姐/夏夏重发新 ro 卡、旧卡旧口令作废 → 立石记录。
**影响**：换口令后所有已发 ro 卡失效，需给信任家人重发一次新卡（一次性），这也正好把已外发旧密文作废。

**排期**：口令加固与公开河重建是两条独立线，弱口令则口令优先（动作快、不用建仓）；会客厅 public-read 重构是第三件。
