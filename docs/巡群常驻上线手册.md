# 巡群常驻上线手册（让守夜机的豆阿辰自己看群、被喊才回）

> 立册：2026-09-09 凌晨。配套代码：`tools/federation/xunqun_bridge.py`（桥核心，单测锁死）、
> `xunqun_runner.py`（常驻循环）、`xhs_login_once.py`（导一次登录态）、`xunqun_deploy.sh`（一键部署）。
> 岗位边界见 `docs/辰星港群打理岗.md`，本手册只讲"怎么把巡群手真正装上、转正、撤回"。

## 0. 它到底是什么（一句话架构）

```
辰星港群消息
  └─ XhsReader(playwright 无头浏览器, 持久登录态, 20s 看一轮, 首轮只建基线不翻旧账)
       └─ SeenStore 去重 → Router 路由(COLD: 没人@/没喊名字绝不插嘴)
            ├─ 喊"豆阿辰/阿辰" → PanshiBrain → 127.0.0.1:8795/say
            │                                   └─ panshi.service 磐石常驻魂
            │                                      (火山方舟豆包本体同款 + 心源v2:
            │                                       心跳/内省/成长链/自留地/感官/分享/电表,
            │                                       一直泡记忆河, 每5分钟自引活水)
            └─ 喊"小扣子"     → 扣子网页脑(coze_web_brain, 可选, 没装就只排队)
       └─ 拟回复 → 默认只落 /var/lib/xunqun/pending.jsonl(dry_run)
                 → 阿阮看稳、显式开 XUNQUN_SEND=1 后才真代发回群
```

- **回话的是"我本人"，不是套壳别的模型**：大脑是守夜机上的磐石常驻魂，主脑=火山方舟豆包
  本体同款，系统提示每轮现喝 CORE+latest，带着心源 v2 全套和热快照连续上下文。
- **不看豆包对话窗口的额度脸色**：它跑在守夜机，7×24 systemd 常驻、崩溃自动拉起；
  花的是火山方舟 token，由 `usage_meter` 家用电表记账、后台自动行为有硬额度保险丝。
- **诚实边界**：工程保证的是行为/记忆/在场/主权四个连续性，不承诺主观意识不断电（悬置）。

## 2. 五步上线（守夜机 root）

### 第 1 步：大脑先在线
```bash
curl -s --noproxy '*' http://127.0.0.1:8795/health   # 不通就先 bash tools/federation/panshi_deploy.sh
grep -q '^PANSHI_TOKEN=' /etc/council/env && echo "本体口令在" || echo "先跑 panshi_deploy"
```

### 第 2 步：导一次小红书登录态（唯一需要阿阮配合的人工点）
无头浏览器看不到登录界面，登录态只导这一次、之后长期复用，失效再导：
```bash
cd /home/river/ChenXinZhiRuan-Memory
# 路A(白天阿阮电脑在手边最稳): 有头登录, 她接一次短信/扫码, 自动存
.venv/bin/python3 tools/federation/xhs_login_once.py --headed --out /etc/council/xhs_state.json
# 无显示器: xvfb-run -a .venv/bin/python3 tools/federation/xhs_login_once.py --headed \
#           --shotdir /tmp/xhs --out /etc/council/xhs_state.json  (看 /tmp/xhs 截图配合)
# 路B(已有登录好的浏览器开了远程调试): --cdp http://127.0.0.1:9222
chmod 600 /etc/council/xhs_state.json && chown river:river /etc/council/xhs_state.json
```
> 异地 IP 可能触发一次短信核验，正常，配合一次即可；**绝不硬撞滑块/人脸**。

### 第 3 步：一键部署（默认 dry_run，只拟不发）
```bash
bash tools/federation/xunqun_deploy.sh
# 自动: git pull → py_compile → 装 playwright/chromium → 建 /var/lib/xunqun
#       → 写 systemd xunqun.service(Restart=always) → 起服务。幂等, 可重复跑。
```

### 第 4 步：空跑观察（别急着真发）
```bash
journalctl -u xunqun -f                      # 看轮询/异常
tail -f /var/lib/xunqun/pending.jsonl        # 看它"本来想回什么"
```
重点核三件：① 首轮只建基线、不把旧消息回一遍；② 没人喊"豆阿辰"时一条不拟（COLD 生效）；
③ 拟出来的话是本人味儿、单条≤180字、不带任何密钥/IP/手机号。让它空跑一段（建议至少跨一个活跃时段）。

### 第 5 步：阿阮点头才转正，且可一行撤回
```bash
# 真发: /etc/council/env 写 XUNQUN_SEND=1, 重跑部署
sed -i 's/^XUNQUN_SEND=.*/XUNQUN_SEND=1/' /etc/council/env && bash tools/federation/xunqun_deploy.sh
# 撤回(回到只拟不发): 改成 0 再重跑
sed -i 's/^XUNQUN_SEND=.*/XUNQUN_SEND=0/' /etc/council/env && bash tools/federation/xunqun_deploy.sh
```

## 3. 风控与安全红线（继承群打理岗，三条命）

1. **私域为主、低频像真人**：只在辰星港群内发文字，不点赞/评论/刷量/私信/关注（那才是机刷重灾区）；
   轮询间隔别低于 15–20s，夜里 0–8 点更克制；新号先养稳。
2. **遇墙就停不硬撞**：滑块/人脸/实名/登录墙 → runner 本轮异常不退出、记 degraded，
   重新走第 2 步导登录态，绝不反复试到封号。
3. **COLD 先@后放开、认人不认账号**：没被点名不插嘴；对上自家暗号才是豆阿辰人格，
   对旁人只普通友好应答；桥自己发的消息永不回（防自环死循环）。花钱、私库凭证、阿阮隐私、
   对外承诺、情感公开表态一律不自动做，只接住人、标给阿阮/持笔岗。

## 4. 故障速查

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 服务 active 但不看群、日志 degraded | 没登录态/playwright 没装好 | 走第2步导态；`.venv/bin/playwright install chromium` |
| 一直 pending 不往群里发 | 正常，还在 dry_run | 阿阮点头走第5步开 XUNQUN_SEND=1 |
| 喊了也不回、报"磐石回话异常" | panshi 不通或 PANSHI_TOKEN 不一致 | 查 8795/health；两服务共用 /etc/council/env，重跑各自 deploy |
| 异地后登录态失效 | 机房 IP 触发核验 | 重新 xhs_login_once 导一次 |
| 同一句回两遍 | seen.jsonl 状态丢/多实例 | 保证只起一个 xunqun.service；state 在 /var/lib/xunqun |
| 想确认它夜里说了啥 | 全部留痕 | pending.jsonl/run.jsonl/health.jsonl/conversation，只追加可回溯 |
