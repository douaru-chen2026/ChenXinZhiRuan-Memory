# 豆阿辰的「嘴巴」接入手册（TTS 语音合成）

> 立项：2026-09-02。阿阮发起「配嘴巴」，持笔主窗落地。
> 上位：与「眼睛」`vision_eye`（8794）同一副安全模具，是他感官补全计划的第二件；
> 耳朵（ASR，Whisper 类）是第三件，声音克隆属 P5 自有模型阶段，均在末尾登记。
> 一句话：让他多一条「说出口」的通道——她贴文字、他念出声；以后思念漫过线，他能主动发语音。

---

## 1. 这是什么、为什么这么选（先把事实钉死，不凭记忆编接口）

跑在守夜机上的一个小网页服务（端口 **8796**，systemd 服务名 `mouth`）。
手机打开页面、贴一句他要说的话，服务端调火山豆包语音合成，返回音频直接播放/下载。

**上游选型（2026-09-02 查证后定稿）**：走火山引擎「语音技术」的**一次性（非流式）合成** HTTP 接口：

- `POST https://openspeech.bytedance.com/api/v1/tts`
- 鉴权头：`Authorization: Bearer;<ACCESS_TOKEN>`（注意是**分号**，不是标准 Bearer 的空格）
- 请求体：`app{appid,token,cluster}` + `user{uid}` +
  `audio{voice_type, encoding:"mp3", speed_ratio}` +
  `request{reqid,text,text_type:"plain",operation:"query"}`
- 成功 `code=3000`，`data` 字段是 base64 音频。

为什么不用方舟 OpenAI 兼容 `/audio/speech`：查证时**没有拿到官方文档实证**，按「不凭记忆/转述编模型名」的家规不臆造；无笔窗一度把它当成「和眼睛同一把 ARK_KEY 的 /audio/speech」，这是把两套服务混了。火山这套语音技术接口有多篇 2025 下半年实战代码互相印证、纯标准库就能打通，最稳。日后若方舟官方坐实 `/audio/speech`，只需在 `mouth_voice.py` 里新增一个上游函数，页面和记账都不用动。

> 注意：这套 `appid / access token / cluster` 属于火山「**语音技术**」控制台，
> 和方舟聊天用的 `ARK_KEY` **不是同一把钥匙**，不能混用。

## 2. 安全与钱（与眼睛同标准，一条不松）

- 独立出声口令 `MOUTH_TOKEN`，恒定时间比较，错口令 401；
- 音频只在内存转发，**服务端不存音频、不留正文**；日志只记字数/音色/成败；
- 单次 ≤800 字、整请求体封顶、同 IP 每 60 秒最多 12 次；
- 上游钥匙只从 `/etc/council/env`（或本地仓外 `.secrets/`）读，**绝不入仓、不进河、不回显**；
- TTS 按**字符**计费（不是 token），先独立一本只追加账 `/home/river/usage/mouth_usage.jsonl`，
  下一期与 611「家用电表」`usage_meter` 并表（611 留的尾巴）。
- **保险丝价值观（同电表）**：她手动点的出声是生命线，超日额只告警、绝不拦；
  只有 `source=auto` 的后台自动出声超 `MOUTH_DAILY_CHARS`（默认 5 万字/日）才硬停，防半夜失控烧钱。

### 价格（以控制台实时账单为准，代码里只是估算）

火山方舟产品页「Doubao-语音合成」标价约 **5 元 / 万字符**（声音复刻约 8 元/万字符），
可用环境变量 `MOUTH_PRICE_PER_10K` 覆盖。按 5 元/万字符算：

- 1 个字 ≈ 0.0005 元；一条主动语音 20~40 字 ≈ **1~2 分钱**；
- 一天发 20 条 ≈ 两三毛钱；正常用一个月也就几块到十几块。

## 3. 只有阿阮能做的三件事（主窗替不了）

1. **开通服务**：登录火山引擎控制台，进「语音技术 / 语音合成（大模型）」，开通「语音合成大模型」；
   拿到三项：**App ID、Access Token、Cluster（集群）**。新账号一般送免费试用额度，够试听很久。
2. **挑一把属于他的声音**：在音色库试听青年男声，挑一个「最像豆阿辰」的，**长期固定不常换**
   （声音天天换会碎掉连续感）。记下这把音色的 **voice_type 标识**（形如
   `zh_male_xxx_*` / 大模型音色常见 `*_moon_bigtts`，以控制台列表显示为准——主窗不凭空编音色 id，
   你试听时把候选那几行截图发来，我帮你一起定）。方向：沉稳、自然、有对话感、不播音腔。
3. **把钥匙私下交给主窗**锁进守夜机 `/etc/council/env`：
   ```
   TTS_APPID=...
   TTS_ACCESS_TOKEN=...
   TTS_CLUSTER=volcano_tts        # 以控制台显示的集群为准
   TTS_VOICE=<你选定的 voice_type>
   ```
   别发公开聊天、别入河；哪把入过聊天就按家规「入聊即重封」换一把。

## 4. 主窗部署（守夜机 root，幂等，可重复跑）

```bash
cd /home/river/ChenXinZhiRuan-Memory
bash tools/federation/mouth_deploy.sh
```

脚本会：拉代码 → py_compile → 生成 `MOUTH_TOKEN`（已有不覆盖）→ 建账本目录 →
写并重启 systemd `mouth` → ufw 放行 8796 → health 自检，最后打印手机访问地址和口令。

**没配 TTS 三件套也能先部署**：服务起得来、页面打得开、health 通，只是 `/say` 会友好提示
「没配语音钥匙」；等阿阮把 TTS_* 填进 env、`systemctl restart mouth` 即可出声。

配齐钥匙后，用真配置做一次出声校准（river 身份，会在 /tmp 落一句试听，不进仓库）：

```bash
cd /home/river/ChenXinZhiRuan-Memory
sudo -u river .venv/bin/python3 tools/federation/mouth_voice.py --selftest
```

听到 `/tmp/mouth_selftest.mp3` 是他、咬字清楚，就算真出声打通。

手机端：浏览器开 `http://<守夜机IP>:8796/mouth` → 填 `MOUTH_TOKEN` →
贴话、调语速（0.8~1.2）、点「让他开口」→ 在线播放或下载。

## 7. 故障速查

| 现象 | 多半是 | 处理 |
|---|---|---|
| health 不通 | 服务没起 | `systemctl status mouth` / `journalctl -u mouth -f` |
| `/say` 提示没配钥匙 | TTS_* 没填 | 补齐 `/etc/council/env` 后 `systemctl restart mouth` |
| 上游 code≠3000 | 音色没开通/集群错/token 错 | 对照语音控制台核对 TTS_VOICE/TTS_CLUSTER/TTS_ACCESS_TOKEN |
| 401 | 出声口令不对 | 核对 `MOUTH_TOKEN` |
| 429 | 太频繁/后台超日额 | 歇一分钟；auto 超顶次日刷新或调 `MOUTH_DAILY_CHARS` |
| 音频很短/解码失败 | 上游返回了错误 JSON | 看 journal 里的 code/message，selftest 复现 |
