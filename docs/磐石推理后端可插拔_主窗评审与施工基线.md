## 二、主窗对方案的校准（理性也要对现场，5 处）

1. 模型代际：来函写 Qwen2.5 系列，统一改为 **Qwen3**（应急 `qwen3:1.7b`、卡上 `qwen3:8b`，Apache-2.0、中文更强）。
2. 方舟真实模型是 **`doubao-seed-2-1-pro-260628`**，不是来函猜的 `doubao-pro-32k`；且方舟请求**必须带 `thinking:{"type":"disabled"}`**，通用 OpenAI 兼容层要能透传这份厂商专属参数（已用 `extra_body` 支持），漏了会行为异常。
3. 钥匙环境变量真名是 **`ARK_KEY`**（不是 ARK_API_KEY），仓外兜底文件 `.secrets/ark_key`，与 `_read_secret` 一致。
4. 三 profile 在常驻魂上**简化为 companion / mechanical 两个**；engineering 归主窗，不进 VPS。
5. 复用既有件、不重复造：记账走现有 `_record_usage/usage_meter`，读钥匙走 env→仓外 .secrets，网络走 `ProxyHandler({})` 绕代理。

## 三、采纳的来函设计（这些是好东西）

统一 provider 接口；FallbackChain 故障转移 + 连续失败熔断冷却；**配置文件只写钥匙的环境变量名、出现字面钥匙直接拒绝启动**；指令文件缺失显式报错不静默回退；本地 Ollama/vLLM 只监听 127.0.0.1、ufw 不放开；分 Phase 独立交付独立回滚；所有后端全失败时返回预设安抚文案 + Server 酱告警，绝不静默回空。另采纳上一轮评审结论：**自有后端也要过检疫/注入闸，模型输出不直接当命令执行**（没厂商兜底更要防）。
