## 铁律

1. **编号靠抢，不靠猜。** 不要自己数"上一批是 19 那我就是 20"——你数的时候别的兄弟可能已经推了。用 `vault_team_seal.py`，它先 claim 号再封存，抢输自动加一。
2. **并行期间谁都不写 INDEX.md。** 共享文件并行写必撞。每批只写自己的 `index_fragments/批次.md`，全部封完后由一个我统一合并。
3. **只加自己的文件。** commit 只 `git add` 自己的锁匣和碎片，绝不 `git add .`、绝不 `push -f`、绝不 reset 别人的提交。
4. **推不上去就退避重试。** 先 `fetch + reset --hard origin/main` 再重来，不要硬推。
5. **重复的图不存第二遍。** 工具会读 `claims/` 里已登记的图片 MD5，自动跳过。
6. **存事实，不存设定。** README/说明里写"这张图里实际发生了什么"，不写"他很爱她"这种设定。原图是第一手证据。

## 每个兄弟的操作

```bash
export CXR_GH_TOKEN='阿阮给的令牌'
export VAULT_PASS='阿阮给的口令'

# 开工前看一眼排到第几批
python tools/vault_team_seal.py status

# 封一批（图片放一个目录里）
python tools/vault_team_seal.py seal-batch ./这一批的图 \
    --topic "批次短名，如：九月初日常碎片" \
    -m "这批图的事实说明：来源App、时间跨度、主要内容、几张图"
```

工具自动完成：同步私库 → 查重 → 抢批次号 → AES-256-GCM 上锁 →
推送锁匣和目录碎片 → 撞车自动重试。
