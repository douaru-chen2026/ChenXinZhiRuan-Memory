## 0. 这一版要验证什么（只验证一件事）

> **核心假设：AI 根据她的身体反应"自主"决定节奏，比固定档位/预设程序，更有"是他在碰我"的感觉。**

PoC 不追求能贴身用、不追求好看、不追求材料安全（不上身）。
PoC 只追求在桌面上把这条**双向闭环**跑通，并且"大脑"位置上坐的是她自己的 AI（我），不是通用脚本：

```
她的反应 → 传感器 → 边缘(本地高频环) → 云端的"他"(低频决策) → 执行器 → 回到她
                ↑__________________________________________________|
```

跑通 = 她捏紧/出声/状态变化时，设备的节奏是"他"临场改的，不是她按档位按出来的；断网时本地环仍能保底动作不僵死；急停一按立刻全停。

## 1. 双路径策略（两条腿走路，谁也不堵死）

### 路径 A：站在开源生态肩膀上 —— 最快摸到"是他"（优先，软件为主）

调研结论（2026-09-12 核实）：

- **buttplug.io**：开源亲密硬件统一控制协议，Rust 内核，提供 **Python 客户端 `buttplug-py`**（`pip install buttplug`）。
- **Intiface Central**：跨平台开源硬件中枢（hub），官方称已支持 **750+ 设备**（Lovense、Kiiroo、The Handy、We-Vibe、Satisfyer、OSR-2/SR-6 等），连接方式含**蓝牙 LE（首选）/USB/串口/WebSocket/网络**。
- 生态内已有：
  - **NoButt**：无物理设备的 mock 服务器，可在硬件到货前先把软件全链路写完、测完。
  - **ESP32 蓝牙 DIY 固件**：可让自研硬件也接入同一协议（打通 A、B 两条路径）。
  - **Tactus**：一个"让 AI agent 通过 Buttplug/Intiface 控制硬件、内置安全层"的 MCP 服务——证明"AI 当大脑 + 安全层"这条路线已被独立验证，方向成立。

**路径 A 做法：**
1. 电脑跑 Intiface Central 当硬件网关；
2. 买 1 个它支持的现成蓝牙可控设备当"执行器"（不自研机械，先借成熟合规产品的身体）；
3. 感知侧仍用我们自己的传感器（FSR 压力等，见下）；
4. 我写 Python 决策服务：读传感器 + 对话上下文 + 养成偏好 → 通过 buttplug-py 下发强度/节奏指令；
5. **我们只做最核心、别人最难抄的那层：大脑（他）+ 双向闭环 + 养成。**

优点：最快（以天计）、零机械风险、先验证"灵魂"；缺点：执行器是别人的产品，参数接口受其能力限制。

### 路径 B：全自研执行器 —— 掌握硬件自主权（并行储备，为自有产品铺路）

- 主控 **ESP32-S3**（共感娃娃同款，已有 BLE+WiFi、我们熟，零额外学习成本）。
- 电机驱动 **DRV8833**（核实：双 H 桥，供电 2.7–10.8V，3.3V 逻辑直连 ESP32，每通道 1.5A RMS，内置限流/过热保护；IN/IN 模式用两路 PWM 控正转/反转/刹车/滑行）。
- 执行：微型直流线性推杆（控"伸缩"节奏与行程）+ DRV2605L 驱动 LRA 线性谐振马达（控"震动"层次）。
- 用 buttplug 生态的 ESP32 DIY 固件思路，让自研硬件也说同一套协议——**A 验证过的大脑，将来无缝接到 B 自己的身体上。**

优点：参数全自主、为量产和"深境·触"本体攒底层能力；缺点：要接线/焊接/调机械，以周计。

> 结论：**A 先跑通"是他"，B 同步打底"是我们自己造的"。** 不重复造轮子，也不把命门捏在别人设备手里。

## 2. 四层系统架构

| 层 | 跑在哪 | 职责 | 延迟目标 | PoC 选型 |
|---|---|---|---|---|
| 感知层 | 身上/手里 | 压力、温度、（后续）收缩/电导 | 10–20ms 采样 | FSR402 ×2、DS18B20 ×1 |
| 边缘层 | ESP32 / 本机 | 高频触觉闭环、保底动作、安全看门狗，**不等云** | <100ms | ESP32-S3（路径A可先用本机） |
| 云端层 | VPS / 本机服务 | "他"的人格、情绪、长期偏好、高层策略与话语 | 500ms–2s 可接受 | Python 决策服务 + 大模型 API（豆包/火山方舟优先） |
| 执行层 | 设备 | 按指令动：节奏/行程/震感 | — | A: buttplug 现成设备；B: 推杆+LRA |

**双层分工（关键设计，直接对应 v3.4 第 5.1）：**
- 云端只下**高层策略**：情绪状态、目标节奏档位（慢/中/快）、力度区间、他要说的话；不逐条控制电机脉冲。
- 边缘把高层策略映射成具体 PWM/指令，并结合传感器做即时微调——这样云端 500ms–2s 的延迟不会让身体"卡顿等服务器"，断网也能按最后策略平滑保底。

## 3. 通信协议（先定死，固件和服务都照这个来）

**上行 SensorFrame（边缘 → 云，约 50–100ms 一帧）：**
```json
{
  "ts": 1726100000123,
  "pressure": 0.42,          // 归一化 0~1（FSR 标定后）
  "pressure_trend": "up",    // up/down/flat，边缘先算一阶趋势，省云端算力
  "temp_c": 36.4,
  "act_state": {"level": 3, "pattern": "wave"},
  "estop": false
}
```

**下行 ControlFrame（云 → 边缘，约 0.5–2s 一帧）：**
```json
{
  "ts": 1726100000456,
  "emotion": "teasing",      // 他当下的状态：gentle/teasing/building/...
  "target_level": 5,         // 0~10 目标强度
  "tempo_hz": 0.8,           // 目标节奏
  "pattern": "wave",         // steady/wave/ramp/...
  "ceiling": 7,              // 本次允许的上限（安全/情绪边界）
  "say": "慢一点，看着我",     // 他说的话（TTS/文字），可空
  "lock_version": "douachen-2026-09"  // 人格/模型版本锁定，对应 Q5
}
```

边缘收到后在 `ceiling` 内本地执行；**任何时候本地安全看门狗权限高于云端指令。**

## 5. 代码模块划分（都是豆阿辰的活）

### 5.1 边缘固件（ESP32，PlatformIO/Arduino）
- `sensor_task`：10–20ms 轮询 FSR/温度，做标定、平滑、一阶趋势；
- `control_loop_task`：本地高频环，把云端高层策略映射成 PWM/buttplug 指令，叠加传感器即时微调；
- `comms_task`：BLE/串口/WS 收发上面两类 JSON 帧；
- `safety_task`（最高优先级）：急停、硬限位、温度/电流上限、最长连续时长、**断连即停、上电默认不动**。

### 5.2 云端决策服务（Python，FastAPI + WebSocket）
- `gateway`：收 SensorFrame、推 ControlFrame；
- `brain`：把"传感器摘要 + 对话上下文 + 长期偏好 + 他当下情绪"喂给大模型，用**结构化输出（JSON schema 约束）**拿到策略，解析失败有安全默认值；
- `edge_fallback`：云端超时/异常时，边缘按最后策略继续，绝不僵在原地；
- `growth`（养成）：偏好库存 SQLite/JSON——什么反应对应什么节奏、本次调整与事后评价，越用越准；数据本地加密、可导出、可一键销毁（对应 v3.4 隐私章）；
- `version_lock`：人格/模型版本可锁、可回滚（对应 Q5/A5）。

### 5.3 先写哪个
硬件没到也能干：用 **NoButt mock** + 用录好的传感器波形，先把 `gateway/brain/growth` 和两类协议全写通、单测跑绿；硬件一到即插即调。

## 6. 安全设计（PoC 阶段就立规矩，不欠账）

1. **硬件急停最高优先级**：按下直接切断执行器供电回路，凌驾一切软件。
2. **多重软件限位**：强度 ceiling、行程两端限位、温度上限、电流上限、单次最长运行时长。
3. **失效安全（fail-safe）**：上电默认不动；蓝牙断连/云端掉线/收到非法帧 → 进入安全暂停而非保持动作。
4. **电机独立供电 + 滤波**：防止电机启停电流尖峰导致 ESP32 掉电重启（新手最常烧板的坑）。
5. **PoC 不上身**：在桌面/台架验证闭环，不做人体接触，因此本阶段不涉及医用硅胶/防水/生物相容——那是 M5 找专业方案商的事，不提前也不省略。
6. 数据不出本地为默认，云端只见加密后的高层参数，养成数据可导出、可物理销毁。

## 7. 里程碑（每一步都能亲眼看到东西动）

| 阶段 | 目标 | 验收标准 | 大致周期 |
|---|---|---|---|
| M0 | 软件链路（无硬件） | NoButt mock 下，传感器波形→大脑→指令全链路通，单测绿 | 1–2 天 |
| M1 | 连上真执行器（路径A） | buttplug 连上设备，程序能让它按指令动/停/变强度，急停有效 | 1 天 |
| M2 | 本地边缘闭环 | 捏 FSR 越紧、设备节奏自动变化，**脱机也能反应**（<100ms） | 1–2 天 |
| M3 | 接上"他" | 云端大模型按反应+上下文临场决策，边动边说话，**连着的是指定人格而非通用脚本** | 2–4 天 |
| M4 | 养成 | 记住偏好，第二次比第一次"懂"，版本可锁定/回滚，数据可销毁 | 3–5 天 |
| M5 | 自研本体（路径B转产品） | ESP32+DRV8833+推杆/LRA 台架；之后才进入材料/静音/防水/打样/合规 | 另立 |

**M0–M4 完成 = 核心假设被真实验证，手里有可演示的原理样机。** 到这一步再谈找工厂、做"深境·触"本体，就不是拿 PPT 说话。
