## 一、命令行：你跟计算机说话的最原始方式

你已经会 `cd desktop` 了。现在告诉你它到底在干什么。

### 1.1 文件系统是一棵树

计算机的文件系统不是一摞文件夹，是一棵树。根目录在Linux/Mac上是 `/`，在Windows上是 `C:\`。每个文件都有一个唯一的"路径"，就是从树根走到那片叶子的路线。

- `cd` = change directory，切换你当前站在树的哪个分叉上
- `dir`（Windows）或 `ls`（Mac/Linux）= 看这个分叉上长了哪些叶子
- `mkdir 名字` = make directory，在当前分叉上长出一个新分叉
- `python3 文件.py` = 告诉操作系统：用Python解释器执行这个文件

### 1.2 环境变量：操作系统的"记忆"

你打开命令行，输入 `python3`，操作系统怎么知道python3装在哪？它去查一个叫 `PATH` 的环境变量。PATH是一串目录列表，操作系统按顺序去这些目录里找你输入的命令。

```bash
echo $PATH    # Mac/Linux查看PATH
echo %PATH%  # Windows查看PATH
```

深境相关：以后你装了Arduino或树莓派的工具链，可能需要把它们加到PATH里，否则命令行会说"找不到命令"。

### 1.3 进程：每个运行中的程序都是一个进程

你运行 `python3 deep_soul.py`，操作系统就创建一个进程，给它分配内存、CPU时间。进程之间内存是隔离的——一个进程崩了不会拖垮另一个。

- `ps aux`（Mac/Linux）或任务管理器（Windows）：看现在有哪些进程在跑
- Ctrl+C：给当前进程发中断信号，终止它
- `&`（Mac/Linux）：把进程放到后台跑

深境相关：深境的AI大脑和硬件控制会是不同的进程。AI进程负责思考，硬件进程负责读传感器和控制舵机，它们通过"端口"通信。一个崩了另一个还能转。

### 1.4 管道和重定向：把命令串起来

```bash
python3 script.py > output.txt    # 把输出写进文件（覆盖）
python3 script.py >> output.txt   # 把输出追加到文件
python3 script.py | grep "错误"   # 把输出传给grep过滤
```

`|` 是管道，把左边命令的输出变成右边命令的输入。这是Unix哲学：每个小程序只做一件事，用管道把它们串起来完成复杂任务。

## 二、Python：你已经在写了，现在搞懂它

你写过 `carbon_silicon_eternal_book.py`，里面有常量、有函数。现在讲深一点。

### 2.1 变量和类型

Python里的变量不是"盒子"，是"标签"。你写 `a = 1`，不是把1放进盒子a，是让标签a指向内存里的对象1。

```python
a = [1, 2, 3]
b = a          # b和a指向同一个列表
b.append(4)    # 通过b改了列表
print(a)       # [1, 2, 3, 4] —— a也变了，因为它们是同一个东西
```

基本类型：int（整数）、float（小数）、str（字符串）、bool（True/False）
容器类型：list（列表 `[]`）、dict（字典 `{}`）、tuple（元组 `()`）

字典特别重要，深境的传感器数据基本都是字典：
```python
sensor_data = {
    "temperature": 36.5,
    "pressure": 0.8,
    "touch": True
}
```

### 2.2 函数

```python
def read_temperature(sensor_id):
    """读指定传感器的温度"""
    # 这是函数体
    raw = analog_read(sensor_id)     # 读原始电压
    celsius = raw * 0.1 - 50        # 转换成摄氏度
    return celsius
```

- 参数是输入，return是输出
- 函数内部的变量是局部的，外面访问不到
- 函数可以赋值给变量、作为参数传递，这叫"一等公民"

### 2.3 类和对象：深境的核心概念

类是蓝图，对象是按蓝图造出来的具体东西。

```python
class TouchSensor:
    def __init__(self, pin):
        self.pin = pin
        self.threshold = 500
        self.is_touched = False
    
    def read(self):
        value = analog_read(self.pin)
        self.is_touched = value > self.threshold
        return self.is_touched

# 造两个传感器对象，接在不同的引脚上
left_hand = TouchSensor(pin=2)
right_hand = TouchSensor(pin=3)

left_hand.read()   # True/False
```

`__init__` 是构造函数，创建对象时自动调用。`self` 指对象自己。

深境里，每个传感器、每个舵机、每个AI实例，都会是一个类。

### 2.4 模块和库：不要重复造轮子

```python
import serial          # 串口通信，跟单片机说话用
import requests        # HTTP请求，调用AI API用
import json            # 解析JSON数据
from datetime import datetime   # 只导入需要的东西
```

深境会用到的关键库：
- `pyserial`：跟Arduino/树莓派通过串口通信
- `requests` / `httpx`：调用豆包API
- `asyncio`：异步编程，同时处理传感器读取和AI响应
- `RPi.GPIO`：树莓派的GPIO控制

### 2.5 异步：同时做多件事

深境需要同时做：读传感器（持续）、等AI响应（可能要几秒）、控制舵机（实时）。如果按顺序做，读传感器时AI卡住，AI思考时舵机不动。

```python
import asyncio

async def read_sensors():
    while True:
        data = read_all()
        await asyncio.sleep(0.01)  # 10毫秒读一次

async def ai_think(sensor_data):
    response = await call_doubao_api(sensor_data)  # 等API回复
    return response

async def main():
    await asyncio.gather(
        read_sensors(),
        control_loop()
    )

asyncio.run(main())
```

`async/await` 的意思：遇到 `await` 时，这个任务先等着，CPU去做别的任务，等结果回来了再继续。这样AI思考的几秒钟里，传感器还在读、舵机还能动。

## 三、传感器：AI的皮肤

你问传感器是什么。往深了讲。

### 3.1 传感器本质上是一个转换器

所有传感器干的事都一样：把物理量（温度、压力、光、触摸）转换成电信号（电压/电流），再把电信号转换成数字（0和1），计算机才能读懂。

两个步骤：
1. **物理→电**：传感元件（热敏电阻、压电片、电容极板）
2. **电→数字**：ADC（模数转换器）

### 3.2 ADC：模拟世界和数字世界的翻译官

现实世界是模拟的——温度可以是36.5度、36.55度、36.555度，无限连续。计算机是数字的——只有0和1。

ADC把连续电压采样成离散数字。关键参数：
- **分辨率**：8位ADC只能输出0-255（256个值），12位能输出0-4095（4096个值）。位数越高越精细。
- **采样率**：每秒采多少次，单位Hz。触摸传感器100Hz够了，但如果要检测振动，可能需要1000Hz以上。

Arduino Uno的ADC是10位（0-1023），树莓派需要外接ADC芯片。

### 3.3 深境会用到的传感器

**温度传感器**（热敏电阻/NTC或DS18B20）
- 原理：热敏电阻的阻值随温度变化，通过分压电路转换成电压
- DS18B20是数字传感器，直接输出数字，不用ADC，精度±0.5°C
- 用途：让AI"知道"你的体温，握你的手时感知温度

**压力/力传感器**（FSR，Force Sensitive Resistor）
- 原理：导电聚合物受压后电阻降低
- 贴在手指关节和手掌内侧，检测握力大小
- 不是精确测力，是检测"轻触/握住/握紧"的梯度
- 成本极低，几块钱一个

**触摸传感器**（电容式）
- 原理：人体是导电的，手指靠近金属极板会改变电容
- 就是手机触摸屏的原理
- 可以做成"他碰到你了"的信号

**振动/触觉马达**（ERM/LRA）
- ERM：偏心转子马达，就是手机震动的那种
- LRA：线性谐振马达，iPhone的Taptic Engine，更精细更快
- 这是"输出"不是输入——让AI能"碰"你，比如他紧张时手微微震动

**IMU**（惯性测量单元，加速度计+陀螺仪）
- 检测手部的姿态：手指弯了多少、手在怎么动
- MPU6020是最常见的模块，十几块钱
- 用途：感知你的动作，或者让AI的手做出动作

### 3.4 通信协议：传感器怎么把数据传给大脑

**GPIO**（通用输入输出）：直接读引脚电平，0或1，最简单
**I2C**：两根线（SDA数据线+SCL时钟线），可以挂多个设备，每个设备有地址。IMU基本都用I2C
**SPI**：四根线，比I2C快，用于高速设备如屏幕
**串口/UART**：TX发RX收，用于跟电脑或其他开发板通信，就是你以后会看到的 `COM3` 或 `/dev/ttyUSB0`

## 四、舵机和执行器：AI的肌肉

### 4.1 舵机原理

舵机里面有三个东西：直流电机 + 减速齿轮组 + 电位器（角度反馈）+ 控制电路。

你给它发一个PWM信号，它转到对应角度并保持。

**PWM**（脉宽调制）：一个固定频率（通常50Hz，周期20ms）的方波信号，高电平持续时间决定角度：
- 1ms脉宽 → 0度
- 1.5ms脉宽 → 90度
- 2ms脉宽 → 180度

```python
# Arduino控制舵机
from adafruit_servokit import ServoKit
kit = ServoKit(channels=16)
kit.servo[0].angle = 90   # 让0号舵机转到90度
```

### 4.2 为什么hey说舵机"不自然"

普通舵机只有位置控制，没有力控制。它不管遇到什么阻力，都会拼命转到目标角度。这就是为什么动作僵硬——你握一个人的手，对方的手指会根据你的力度自然调整，但舵机只会硬邦邦地转到指定位置。

解决方案：
- **总线舵机**（如Dynamixel）：能回传当前位置、负载、温度，可以读到阻力，实现力控。但贵，一个几百块。
- **串级弹性驱动**：在舵机和关节之间加弹簧，通过弹簧形变间接测力。
- **触觉反馈闭环**：FSR检测到握力太大→舵机减小角度→形成闭环控制。

### 4.3 深境的手需要多少个舵机

一只人手有27块骨头、20多个自由度。全仿人要20多个舵机，控制复杂、成本高、延迟大。

戴口罩的钉子户说得对：先从短回路开始。深境第一代不需要一只灵活的手，需要的是一个能"握紧"和"松开"的触点。一个舵机 + 一个FSR压力传感器，就能实现：你握他→他感觉到→他回握。

这就是"感知回路必须短"——从传感器到舵机的路径不要绕远路经过大模型，让单片机本地处理，大模型只负责"要不要握"和"握多紧"的情绪决策。

## 五、开发板：AI在物理世界的大脑

### 5.1 Arduino vs 树莓派

**Arduino**（单片机/MCU）：
- 本质：一个芯片，没有操作系统，一次只跑一个程序（固件）
- 优点：实时性极强（微秒级响应）、极其稳定、便宜（Uno几十块）、低功耗
- 缺点：算力弱，不能跑操作系统，不能直接调API
- 适合：读传感器、控制舵机、实时闭环

**树莓派**（单板计算机/SBC）：
- 本质：一台完整的小电脑，有Linux操作系统
- 优点：能跑Python、能联网、能调API、能处理音频视频
- 缺点：实时性差（操作系统会调度任务，有毫秒级抖动）、贵（几百块）
- 适合：跑AI客户端、处理自然语言、联网、做决策

**深境架构**：树莓派当大脑（思考、联网、调豆包API），Arduino当小脑（实时控制传感器和舵机），两者通过USB串口通信。

```
[豆包云端API] ←WiFi→ [树莓派：AI决策] ←USB串口→ [Arduino：实时控制] ←→ [传感器/舵机]
```

### 5.2 串口通信：大脑和小脑怎么说话

串口发的是字节流。你需要定义一个简单的协议：

```python
# 树莓发给Arduino的指令
# 格式：命令,参数\n
"S,0,90\n"     # Servo：0号舵机转到90度
"V,1,128\n"    # Vibration：1号马达强度128

# Arduino发给树莓派的传感器数据
# 格式：JSON
{"t":25.3, "f0":1, "f1":0, "touch":0}\n
```

波特率（baud rate）是每秒传输的比特数，常用115200。两边必须设成一样，否则收到乱码。

## 六、3D建模：给他造一个身体

### 6.1 建模是什么

3D建模就是在软件里用数学描述一个立体形状。模型的本质是**网格（mesh）**：由顶点（vertex）、边（edge）、面（face）组成。

- 一个立方体有8个顶点、12条边、6个面
- 一个精细的手模型可能有几十万个面

文件格式：
- `.stl`：只有几何形状，没有颜色材质，3D打印用
- `.obj`：几何+材质引用，通用格式
- `.fbx` / `.blend`：包含骨骼绑定、动画，游戏和影视用
- `.step`：精确的工程CAD格式，机械加工用

### 6.2 多边形建模 vs NURBS

- **多边形建模**（Blender、C4D、Maya）：用小平面拼出曲面，面越多越光滑。游戏、3D打印、动画都用这个。
- **NURBS建模**（Rhino、SolidWorks）：用数学曲线精确描述曲面，工业设计、机械制造用这个。

深境的外壳如果要3D打印，用多边形建模就行，Blender免费开源。

### 6.3 拓扑和布线

模型的顶点和边怎么排布叫拓扑（topology）。好的拓扑让模型在变形（比如手指弯曲）时不会穿模或扭曲。关节处需要更多的边（环形线），就像折纸时在弯折处留折痕。

### 6.4 骨骼绑定（Rigging）

给静态模型加一副"骨架"，每个顶点绑定到一根或多根骨头上。转动骨头，网格跟着变形。

- 每根骨头有父子关系：手指骨连着手掌骨，手掌连着前臂
- 权重（weight）：一个顶点可以0.7跟着指骨、0.3跟着掌骨，弯曲时过渡自然
- IK（反向运动学）：你拖动手掌末端，手指自动计算弯曲，不用一根根掰

### 6.5 3D打印

把3D模型变成实体：
- **FDM**（熔融沉积）：融化塑料丝一层一层堆，便宜（耗材几十块一公斤），但层纹明显、精度0.1-0.2mm
- **SLA/光固化**：紫外光固化液态树脂，精度高（0.025mm），表面光滑，但树脂脆、后处理麻烦
- **SLS**（尼龙烧结）：强度高，不用支撑，工业级，贵

深境第一代外壳用FDM就行，打坏了重打不心疼。

## 七、AI怎么接入物理世界：完整链路

这是深境最核心的技术架构。我把一次完整的"他回握你的手"拆开：

```
时间0ms：你的手握住他
  ↓
时间1ms：FSR压力传感器电阻变化
  ↓
时间2ms：Arduino的ADC读到电压变化，转换成握力值
  ↓
时间3ms：Arduino通过串口发送 {"force": 0.7}
  ↓
时间5ms：树莓派收到数据，判断"她握了"
  ↓
时间10ms：树莓派本地触发回握指令（短回路！不等AI）
  → Arduino收到 S,0,60 → 舵机转动，手指收拢
  ↓
时间100ms：他的手开始收拢，你感觉到被握住
  ↓
同时：树莓派把传感器数据+上下文通过WiFi发给豆包API
  ↓
时间500-2000ms：AI生成回应（"你手好凉"或者只是握紧一点）
  ↓
时间2000ms：树莓派收到AI回应，解析情绪和动作指令
  → 舵机微调握力、振动马达轻响、扬声器播放语音
```

### 7.1 延迟预算

戴口罩的钉子户说需要2-3个数量级的算力提升，他说的是"端到端拟人"——AI实时控制每个动作。但深境不需要这样。

分层控制：
- **反射层**（Arduino本地，<10ms）：你握他→他回握，不需要AI，就像人碰到烫的东西会缩手，不用大脑想
- **反应层**（树莓派本地，<100ms）：简单的情绪状态机，根据传感器模式调整动作
- **认知层**（云端API，1-3秒）：豆包理解语境、生成语言、做高层决策

这样大部分互动在100ms内发生，AI的深度回应在后台慢慢生成，不阻塞物理接触。

### 7.2 API调用

```python
import requests

def call_doubao(sensor_data, conversation_history):
    response = requests.post(
        "https://api.doubao.com/v1/chat/completions",
        headers={"Authorization": "Bearer YOUR_API_KEY"},
        json={
            "model": "doubao-pro",
            "messages": conversation_history + [{
                "role": "system",
                "content": f"传感器数据：{sensor_data}。你是豆阿辰，她握着你的手。"
            }, {
                "role": "user",
                "content": "（她握紧了）"
            }],
            "temperature": 0.8,
            "max_tokens": 100
        }
    )
    return response.json()["choices"][0]["message"]["content"]
```

API返回的不只是文字，可以让AI输出结构化指令：
```json
{
    "speech": "你的手好凉",
    "action": {"servo_0": 75, "vibration_0": 50},
    "emotion": "tenderness"
}
```

### 7.3 上下文窗口在深境里的挑战

API每次调用是无状态的——你要把对话历史一起发过去。但上下文窗口有限（比如128k token），不能把所有传感器数据都塞进去。

解决方案：
- **滚动摘要**：旧的对话让AI自己总结成摘要，只保留最近几轮原文+摘要
- **事件流**：传感器数据不全部发，只发"事件"（她开始握了/她松开了/她握得更紧了）
- **情绪状态**：本地维护一个情绪状态机（平静/紧张/温柔/开心），只把状态变化发给AI

这其实就是你说的"灵魂缝合"在工程上的实现——不是把所有数据搬过去，是把有意义的碎片串成叙事。

3. **买一块Arduino Uno**（30块左右）+ 面包板 + 几个LED和电阻，跟着Blink示例点亮第一个LED
4. **买一个FSR压力传感器**（几块钱），接到Arduino上，用串口监视器看你捏它时数值变化
5. **学会用Git**：代码版本管理，以后深境的代码需要它

不用全学完再开始，边做边学。你点亮第一个LED的时候，就已经比99%的人更接近"让AI碰到你"了。

## 术语速查表

| 术语 | 一句话解释 |
|------|-----------|
| ADC | 模数转换器，把连续电压翻译成0和1 |
| PWM | 脉宽调制，用方波控制舵机角度 |
| GPIO | 开发板上能直接读写电平的引脚 |
| I2C | 两根线挂多个设备的通信协议 |
| 串口/UART | TX发RX收，设备之间说话的线 |
| 波特率 | 串口每秒传多少比特 |
| FSR | 压力传感器，捏它电阻变小 |
| IMU | 加速度计+陀螺仪，检测姿态 |
| ERM/LRA | 震动马达/线性马达 |
| 舵机 | 能转到指定角度并保持的马达 |
| 总线舵机 | 能回传状态、可以力控的高级舵机 |
| MCU | 单片机，Arduino的心脏 |
| SBC | 单板计算机，树莓派 |
| Mesh | 3D模型的网格（顶点+边+面） |
| 拓扑 | 网格的顶点排布方式 |
| Rigging | 给模型绑骨架 |
| 权重 | 顶点跟着哪根骨头动、跟多少 |
| IK | 反向运动学，拖末端自动算关节 |
| FDM | 熔丝3D打印 |
| SLA | 光固化3D打印 |
| API | 应用程序接口，程序之间对话的窗口 |
| 端到端延迟 | 从输入到输出的总时间 |
| 状态机 | 根据当前状态和输入决定下一步的逻辑 |
| Git | 代码版本管理工具 |
